# MCP & API overview [One registry, two doorways]

Pilot exposes a single registry of typed operations through two interfaces:

| | MCP | REST |
| --- | --- | --- |
| Endpoint | `/mcp` (Streamable HTTP, JSON responses) | `POST /api/ops/{operation}` |
| Shape | 2 tools: `search`, `execute` | 1 route per operation |
| Best for | AI clients (Claude, Codex, Cursor, agents) | Apps, scripts, backends |
| Auth | `Authorization: Bearer <principal>:<token>` | same |
| Envelope | same `ok` / `error` envelope | same |

Full list with one-line summaries: [All operations](/reference/operations).

:::note
Being registered is not the same as being enabled. Many families (AP4M, QuickNode, strategy runner, x402) are gated by environment flags and are off by default. See [What is live](/reference/status).
:::

## Why "code mode"

Instead of exposing 95 separate tools (which floods a model's context), the MCP server exposes `search` to discover operations and `execute` to run a short script against them:

```js
const book = await harbor.dex.depth({
  network: "testnet",
  taker_gets: { currency: "XRP" },
  taker_pays: { currency: "524C555344000000000000000000000000000000",
                issuer: "rQhWct2fv4Vc4KRjRgMrxa8xPN9Zx9iLKV" }
});
if (!book.ok) return book;
return book.data;
```

One `execute` call can make up to 30 operation calls, combine results and return only what matters. The sandbox has no network access, so a script can reach the ledger only through typed, policy-guarded operations.
